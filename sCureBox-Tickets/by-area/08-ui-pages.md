# 08 — Native UI (src/SCureBox.Ui, pages / shell / services / controls)

Scope of this file: everything in `src/SCureBox.Ui` except the dialogs (`Views/Dialogs`, `ViewModels/Dialogs`, `Dialogs/` = `IDialogService`, `DialogService`, `DialogViewModel` — see the "Native UI dialogs" tickets). Dialog view models are referenced here by their exact class name and the result type the pages await.

## Native UI — overview

**What it is.** `scurebox-ui` is ONE .NET process: it builds the firmware ASP.NET Core host (hardware + process + platform layers, `/api` on :3001, systemd READY/WATCHDOG) with `ScureApiHost.Build(args, b => b.Services.AddSCureBoxUi())`, starts it, then runs Avalonia 12 on the main thread with the host's `IServiceProvider` as the DI root. View models call the in-process services directly (`ICureController`, `IRecipeRunner`, `IMaterialStore`, `ICureRunStore`, `IPrintHistoryStore`, `IPhaseTimingStore`, `INetworkService`, `ISystemService`, `INfcReaderDetector`, `ILedCalibrationStore`, `IComponentCounters`, `IHdtCalibration`, `ITemperatureProbe`, `ICureReportBuilder`, `IHdtReportBuilder`, `ErrorRegistry`, `TimeProvider`, …). **The UI never calls the HTTP API.** The only HTTP surface this project adds is the QA group `/api/ui/*` (UI-08).

**Stack.** `net10.0` (from the repo's shared build props — OPEN QUESTION: the csproj itself sets no TargetFramework; take it from Directory.Build.props of the solution), Avalonia 12.1.4 (`Avalonia`, `Avalonia.Desktop`, `Avalonia.LinuxFramebuffer`, `Avalonia.Themes.Fluent`, `Avalonia.Fonts.Inter`, `Avalonia.Skia`, `Avalonia.HarfBuzz`, `Avalonia.Wayland`), CommunityToolkit.Mvvm 8.4.2 (`[ObservableProperty]`, `[RelayCommand]` — all VM property / command names below are the generated public names), Microsoft.Extensions.Hosting(.Systemd) 10.0.13. Compiled bindings by default (`AvaloniaUseCompiledBindingsByDefault=true`). AssemblyName `scurebox-ui`, RootNamespace `SCureBox.Ui`, `InternalsVisibleTo SCureBox.Ui.Tests`. Project references: `SCureBox.Application`, `SCureBox.Api`.

**Design surface.** Every screen is laid out on a fixed **1600 x 1000** design surface (`ShellView` Width=1600 Height=1000), scaled uniformly into the output by `ShellScaler` (Viewbox, letterboxed on black) and rotated 90° when the output is portrait (the 10.1" Touch Display 2 is portrait-native 1200x1920). All sizes in these tickets are design pixels (React spec px x 2).

**Shell layout.** `ShellView` = Grid with layers bottom→top: `PageLayer` (row 0: `TopBar` 96 px high, hidden on full-screen routes; row 1: `PageHost` ContentControl bound to `CurrentPage`), `PageFade` (page crossfade still, disabled by default), `PageBlur` (opaque blurred still of the page while a dialog is up), `DialogHost` (modal host), `FloatLayer` (Canvas for drop-down lists).

**Conventions used by every page.**
1. Every page VM derives from `PageViewModel` (abstract `Route Route`, abstract `string Title`, virtual `OnNavigatedTo(object? parameter)`, virtual `OnNavigatedFrom()`); one instance is created per navigation through DI (`ActivatorUtilities.CreateInstance`). Subscriptions to singleton events (`MachineStateStore.Updated`, `AlertService.Changed`, `UiSettingsStore.Changed`, `DevModeService.Changed`) are attached in `OnNavigatedTo` and detached in `OnNavigatedFrom`; timers are stopped in `OnNavigatedFrom`.
2. Every user-visible string lives in `Resources/Strings*.cs` (`static partial class Strings` with nested static classes); views use `{x:Static s:Strings+Group.Name}`. US English. Titles are white, never blue.
3. No Avalonia popup controls anywhere (`ComboBox`, `Flyout`, `MenuFlyout`, `ContextMenu`, `Popup`, `AutoCompleteBox`, `DatePicker`, `TimePicker` are forbidden — a test greps all .axaml). Choices are segmented buttons, `FloatingList` or a dialog.
4. Hardware calls that can block (LED test, fan test, recipe start, exports, network status, diagnostics) run in `Task.Run`; only results are applied on the UI thread.
5. `OpResult` (Domain.Errors) = `{ Ok, Message, Code? }`; a refused command is usually logged and, where stated, raised as an alert with `r.Code ?? <fallback code>`.
6. Error codes used here: 3001 SerialRestoreFailed, 4003 SdBackupWriteFailed, 6015 HardwareRefused, 6016 DoorAbort, 7004 TemperatureStall, 9001 TempSensorDisconnected (family), 9002 FanFailure (family 902x), 9003 LedFanStopped (family 903x), 9004 LedNotHeating (per panel 9040/9041/9044/9045 via `ErrorCodes.LedNotHeatingOf(panel)`), 9006 TempReadingFrozen, 9010 ChamberSensorDisconnected, 9016 N2 sensor not reading, 9017 WatchdogTripped, 9051 FanWearWarning (family 906x), 9052 NfcReaderNotDetected, 9081 NoUsbDrive, 9082 UsbWriteFailed, 9083 LogExportFailed, 9084 NetworkError, 9085 DiagnosticFailed, 9089 ApiUnreachable. `ErrorCodes.IsA(code, family)` and `ErrorCodes.Family(code)` come from Domain.

### UI-01 — App shell, hosting, DI registration and PC demo mode
**Summary**
- **What it is for:** The main frame of the machine's touch screen app. It starts the machine software and the screen in one program and holds every page.
- **Problem it solves:** Without it the screen and the machine control would run apart, the picture would not fit or rotate on the panel, and a stop or restart could hang for a long time.
- **How we solve it:** One program starts the machine service, then draws a fixed-size screen that scales and turns to fit the panel. Any stop request ends the program within 10 seconds. A demo file turns it into a PC simulator.

**Project / folder:** `src/SCureBox.Ui/SCureBox.Ui.csproj` — root (`Program.cs`, `App.axaml(.cs)`, `UiPages.cs`, `UiServiceCollectionExtensions.cs`, `ViewLocator.cs`, `app.manifest`), `Hosting/`, `Views/ShellView.axaml(.cs)`, `Views/ShellScaler.cs`, `Views/ShellWindow.cs`, `ViewModels/ShellViewModel.cs`, `ViewModels/PageViewModel.cs`, `Services/UiRuntime.cs`
**Goal:** Run the firmware host and the Avalonia UI in one process with one DI container, choose the output (DRM/KMS on the unit, a desktop window elsewhere), guarantee the process exits within 10 s of any stop request with the "Restarting…" frame on the panel, and host every page inside a 1600x1000 shell that scales/rotates to the output, blurs behind dialogs and resets the idle timer on every touch. A `demo.mode` file next to the exe turns the app into the PC simulator.
**Depends on:** UI-02, UI-05, UI-06, UI-09, UI-10; Api (`ScureApiHost.Build`, `CommandLine.TryRun`, `IApiEndpointMapper`, `ApiJson`), Application-Platform (`PlatformInfo`, `PlannedRestart`, `DataOptions`, `SerialBackup`), Native UI dialogs (`IDialogService`, `DialogService`, `DialogViewModel`)

**Behaviour & rules:**
1. `Main`: (a) `DemoMode.ApplyFromProcess()`; (b) `CommandLine.TryRun(args, Console.Out, Console.Error, out exit)` — if it handled a CLI tool command return its exit code; (c) `app = ScureApiHost.Build(args, b => b.Services.AddSCureBoxUi())`, logger category "UI", `app.StartAsync().GetAwaiter().GetResult()`, `App.Services = app.Services`; (d) register on `app.Lifetime.ApplicationStopping`: if the UI already stopped, return; else start background thread "hard-exit-deadline" that sleeps 10 s then logs an error and `HardExit(0)`; call `PlannedRestart.Mark("host stopping")` if registered (next boot = quick boot); `Dispatcher.UIThread.Post` a `Navigate(Route.Restart, null, replace: true)`; sleep 400 ms; `Post(App.RequestShutdown)`; then start thread "ui-stop-guard": sleep 4 s, if the UI loop has not ended, `app.StopAsync` with a 10 s token, then `HardExit(0)`. (e) `exit = RunAvalonia(args, log)`; in `finally`: mark UI stopped, `app.StopAsync` bounded by 5 s (wait 6 s), `app.DisposeAsync` bounded by 2 s, then `HardExit(exit)`.
2. `HardExit(status)`: on Linux P/Invoke `libc _exit(status)`; else `Process.GetCurrentProcess().Kill()`; last resort `Environment.Exit(status)`. Reason: worker threads and DRM exit handlers keep the process alive until systemd SIGKILLs it at 90 s.
3. `RunAvalonia`: `SCURE_UI_WINDOW` truthy forces a window. `UiMotion.Enabled = Truthy(SCURE_UI_ANIMATIONS)` (animations OFF unless asked). Builder = `AppBuilder.Configure<App>().UseSkia().UseHarfBuzz().WithInterFont().LogToTrace()` (UseHarfBuzz is mandatory: the DRM path crashed without a text shaper). Linux and not forced window → `card = DrmCards.Select(env SCURE_UI_DRM_CARD)`, `App.HideCursor = true`, `return builder.StartLinuxDrm(args, card, 1.0)`. Otherwise: `App.HideCursor = Truthy(SCURE_UI_HIDE_CURSOR)`, `App.FullScreen = Truthy(SCURE_UI_FULLSCREEN)`, `App.WindowSize = ParseSize(SCURE_UI_SIZE) ?? 1920x1200`; `builder.UsePlatformDetect().UseWaylandWithFallback()`; `SCURE_UI_RENDER` (trimmed lower): `gles` → `WaylandPlatformOptions.GlProfiles = [OpenGLES 3.1, 3.0, 2.0]`; `software` → `WaylandPlatformOptions{GlProfiles = empty, UseDmabufSwapchain = false}` + `X11PlatformOptions{RenderingMode = [Software]}`; `StartWithClassicDesktopLifetime(args, ShutdownMode.OnMainWindowClose)`.
4. `Truthy(v)`: trimmed lower-case is "1", "true" or "yes". `ParseSize("WxH")`: case-insensitive "x" split, exactly 2 ints, w ≥ 200 and h ≥ 120, else null.
5. `DemoMode.Environment(root)` = SCURE_SIMULATE=1, SCURE_UI_WINDOW=1, SCURE_UI_SIZE=1600x1000, PORT=3011, ASPNETCORE_URLS=http://127.0.0.1:3011, SCURE_DATA_DIR=<root>/data. `Apply`: returns false when `<baseDir>/demo.mode` does not exist; root = `<localAppData or baseDir>/sCureBox Demo`; each variable is set only when `get(name)` is null/whitespace (environment wins); returns true.
6. `DrmCards.Select`: a non-blank override is returned trimmed; else `Scan` → `/dev/dri/<cardN>` or null. `Scan`: directories `card*-*` under sysClassDrm sorted ordinal; name split at first '-' (skip if dash index ≤ 4); first card with any connector remembered; a connector whose `status` file reads "connected" (case-insensitive) wins immediately; IO/permission errors ignored; missing dir → null.
7. `App.axaml`: `RequestedThemeVariant="Dark"`, DataTemplates = `ViewLocator`; resources merge `avares://scurebox-ui/Styles/Tokens.axaml` and `.../Styles/ScrollViewer.axaml`; styles = `FluentTheme` then `avares://scurebox-ui/Styles/Controls.axaml`.
8. `OnFrameworkInitializationCompleted` (only when `Services` is set; headless tests leave it null): create `ShellView { DataContext = ShellViewModel }`, `runtime.ShellRoot = shell`, wrap in `new ShellScaler(shell)`; desktop lifetime → `new ShellWindow(scaler, WindowSize, HideCursor, FullScreen)` as MainWindow and `runtime.TopLevel = window`; single-view lifetime (DRM) → `MainView = scaler`, TopLevel set when the scaler attaches; then `runtime.Start()`. `RequestShutdown()` calls `Shutdown()` only if the lifetime is `IControlledApplicationLifetime`.
9. `AddSCureBoxUi` registers: `TryAddSingleton(TimeProvider.System)`, `TryAddSingleton<SerialBackup>(new SerialBackup())`, singletons `UiSettingsStore`, `MachineStateStore`, `AlertService`, `DevModeService`, `IdleService`, `BarcodeScanner`, `RemoteConfirmPrompter`, `NfcJobService`, `TryAddSingleton<IOriginBrowserSignIn, OriginBrowserSignIn>`, `UiRuntime`, `INavigationService→NavigationService`, `IDialogService→DialogService`, `TopBarViewModel`, `ShellViewModel`, `TryAddSingleton(BootTimings.Default)`, `TryAddSingleton<IBootSelfTest, HardwareBootSelfTest>`, every page VM type of `UiPages.All` as transient, `AddSingleton<IApiEndpointMapper, UiEndpoints>`. (TryAdd lets tests pre-register fakes.)
10. `UiPages.All` order and titles exactly as the overview table. `UiPages.Dialogs` maps 24 dialog VMs to views: OnScreenKeyboard, NumberPad, MessageDialog, CriticalAlertDialog, NitrogenOnlyDialog, PreflightDialog, FanFailDialog, UsbFileBrowserDialog, DevAuthDialog, AbortDialog, PauseDialog, PauseOverlay, HeaterFaultDialog, TemperatureWarningDialog, CureCompleteDialog, DoorOpenDialog, PrintHistoryDialog, VersionsDialog, ComplianceDialog, SoftwareUpdateDialog, StaticIpDialog, MaterialEditorDialog, ImportCsvDialog, OriginSignInDialog (each `XxxViewModel → XxxView`; keyboard/numberpad are `OnScreenKeyboardViewModel→OnScreenKeyboardView`, `NumberPadViewModel→NumberPadView`). `ViewFor` looks up a merged map of both. `DialogsAreValid()` = every key is assignable to `DialogViewModel`.

12. `ShellViewModel`: on `navigation.Changed` → `CurrentPage = navigation.CurrentPage`, `ShowTopBar = !Current.IsFullScreen()`, and if a dialog is open `dialogs.CloseAll(pageChange: true)` (dialogs belong to the page that opened them, except those with `KeepAcrossPageChange`). On `dialogs.Changed` → `BelowDialog = dialogs.Below; Dialog = dialogs.Current`. Calls `OnNavigated()` once in the ctor. `Touch()` → `IdleService.Touch()`.
13. `ShellView` (1600x1000, Background `BackgroundBrush`, ClipToBounds): TopBar `IsVisible` bound to `ShowTopBar`; `DialogHost Dialog={Binding Dialog} Below={Binding BelowDialog}`. Tunnel handlers (handledEventsToo) for PointerPressed and PointerMoved call `ShellViewModel.Touch()`. A static class handler on `ScrollContentPresenter.RequestBringIntoViewEvent` marks the event handled when the presenter is inside a `ShellView` whose `DialogIsUp` (`Dialogs.HasDialog || Dialogs.FadeProgress > 0`) — a modal must never scroll the page behind it.
14. Dialog blur: when `DialogHost.HasDialog` turns true, `PrepareDialogBlur()` immediately renders `PageLayer` into a `RenderTargetBitmap` at scale 0.08 (pixel size ≥ 2x2, DPI 96·scale) with `TextOptions.TextRenderingMode = Antialias` temporarily (greyscale — subpixel AA produced coloured confetti) and sets it as `ImageBrush{Stretch=Fill}` background of `PageBlurStill`; `PageBlur` (outer border, opaque `BackgroundBrush`) shows it. On every `DialogHost.FadeProgress` change: progress > 0.001 → ensure still, `PageBlur.Opacity = DialogHost.Ease(progress)`; else hide, opacity 0, dispose and drop the still. A capture failure returns null and is never fatal. When `CurrentPage` changes while a dialog is open, after the next `PageLayer.LayoutUpdated` take a fresh still (keep the old one if the capture fails). Never use an Avalonia blur `Effect` (it ignores the 90° rotation and drew upside down).
15. Page fade (off by default, `PageFadeEnabled=false`): on `PropertyChanging(CurrentPage)` capture the page at 0.5 scale into `PageFade` (opacity 1) and on `PropertyChanged(CurrentPage)` tween it to 0 over 200 ms (`Tween(…, 200, 16)`); at ≤ 0.001 hide and dispose.
16. `ShellScaler`: Background black; `Content = Viewbox{Stretch=Uniform, StretchDirection=Both, Child = LayoutTransformControl{Child = shell}}`; on SizeChanged `Resolve(size)` = 90 when Height > Width else 0; apply `RotateTransform(90)` (or null) only when it changed. Touch follows the transform.
17. `ShellWindow`: Title `Strings.AppName` ("sCure"), fixed Width/Height, `CanResize=false`, `WindowDecorations = None`, Background black, CenterScreen, `WindowState = FullScreen` only when `fullScreen`, `Cursor = None` when `hideCursor`.
18. `UiRuntime.Start(skipBoot)`: idempotent; starts `MachineStateStore`, `AlertService`, `IdleService`, `BarcodeScanner`, `RemoteConfirmPrompter`, `NfcJobService`; then `Navigate(Route.Boot, replace: true)` (or, with skipBoot, Home if `SetupComplete` else Setup). `Stop()` stops idle, alerts, store and clears `Started`.
**Configuration:** env `SCURE_UI_WINDOW`, `SCURE_UI_ANIMATIONS`, `SCURE_UI_DRM_CARD`, `SCURE_UI_HIDE_CURSOR`, `SCURE_UI_FULLSCREEN`, `SCURE_UI_SIZE` ("WxH"), `SCURE_UI_RENDER` (`gles` | `software`); demo marker file `demo.mode` beside the exe (sets SCURE_SIMULATE, SCURE_UI_WINDOW, SCURE_UI_SIZE, PORT, ASPNETCORE_URLS, SCURE_DATA_DIR); csproj property `DemoWinExe=true` makes OutputType `WinExe` (no console window for the PC demo installer).

### UI-02 — Theme, design tokens, global styles and string resources
**Summary**
- **What it is for:** The look of the screen app: dark colors, text sizes, corner shapes, button and card styles, and one list of all on-screen texts.
- **Problem it solves:** Without one shared style, each page would look different, touch targets could be too small, and texts would be scattered and hard to change.
- **How we solve it:** We define all colors, sizes and button styles once and every page uses only them. All user-visible words live in one text catalogue in US English.

**Project / folder:** `src/SCureBox.Ui/SCureBox.Ui.csproj` — `Styles/`, `Resources/`, `branding/` (repo root)
**Goal:** Provide the dark-only visual language (colours, typography, radii, touch sizes, button/card/pill/toggle themes, touch-sized slider, scroll viewer with the custom touch recognizer) on the 1600x1000 surface, and the single catalogue of user-visible strings. Every view uses only these tokens and classes.

### UI-03 — Reusable controls (Controls/)
**Summary**
- **What it is for:** The set of building blocks the pages are made from: buttons with icons, cards, status pills, switches, the logo, progress rings, charts, a QR code maker, drop-down lists and the dialog holder.
- **Problem it solves:** Without shared blocks each page would rebuild the same parts, and outside icon, chart or QR packages would add weight and risk.
- **How we solve it:** We draw all these parts ourselves in code, with no outside packages, and reuse them on every page.

**Project / folder:** `src/SCureBox.Ui/SCureBox.Ui.csproj` — `Controls/`
**Goal:** The drawn, dependency-free control set the pages are built from: surfaces (Card, StatusPill, Toggle), the app button with vector icons, the S logo, progress ring and gauges, the phase card of the cure page, the editor step card view, a popup-free drop-down (`FloatingList`), the heating track veil, a tiny QR encoder, two charts and the in-shell modal host. No icon fonts, chart or QR packages.

### UI-04 — Touch gestures: SwipeRow and TouchScrollGestureRecognizer
**Summary**
- **What it is for:** Touch handling: smooth finger scrolling and list rows you can swipe right to run or left to show actions.
- **Problem it solves:** On the turned panel, scrolling can feel jumpy or wrong, and a careless swipe could start a cure by accident or fight with page scrolling.
- **How we solve it:** A custom scroll handler measures the finger correctly, filters panel noise and moves on each drawn frame. The swipe row needs a clear, deliberate gesture before it starts anything.

**Project / folder:** `src/SCureBox.Ui/SCureBox.Ui.csproj` — `Controls/SwipeRow.cs`, `Controls/TouchScrollGestureRecognizer.cs`
**Goal:** Make touch feel right on the rotated portrait panel: a scroll recognizer that measures the finger in the scrolled control's own coordinates, damps panel noise, fits fling velocity robustly and steps all motion on rendered frames; and a swipeable list row (right = run, left = uncover an action tray) that can never start a cure by accident and never fights the page scroll.
**Depends on:** UI-02 (SwipeRow theme, ScrollViewer theme), UI-05 (`UiMotion` is NOT consulted by the row)
**Files to create:**
- `Controls/SwipeRow.cs` — `public enum SwipeAction { None, Start, Open, Close }`, `public class SwipeRow : ContentControl` (TemplateParts `PART_Row`, `PART_Start`, `PART_Actions`; pseudo-classes `:swiping`, `:armed`, `:open`, `:revealed`)
- `Controls/TouchScrollGestureRecognizer.cs` — `public sealed class TouchScrollGestureRecognizer : GestureRecognizer`, `internal sealed class FlingTracker`
**Public contract:**
- `SwipeRow` constants: `StartDistance = 14`, `StartFraction = 0.5`, `ActivateStart = 180`, `ActivateOpen = 120`, `ActivateClose = 60`, `AxisRatio = 1.2`, `Overshoot = 24`, `PxPerMm = 7.4`, `ActionsRevealMm = 5`, `SnapMs = 180`, `CompleteMs = 160`. Statics: `double StartThreshold(double rowWidth) = max(180, rowWidth·0.5)`, `SwipeAction Decide(double dx, double dy, bool open, bool canStart, bool canOpen, double rowWidth = 0)`, `double ActionsOpacity(double x)`, `bool IsClaimed(IPointer)`. Styled props: `Actions` (object?), `OpenWidth` (double), `IsOpen` (bool, TwoWay default), `StartCommand` (ICommand?), `SwipeEnabled` (true), `StartText` (""). Read-only: `SwipeAction LastAction`, `double Offset`. Method `void FinishMotion()`.
- `TouchScrollGestureRecognizer` styled props `CanHorizontallyScroll`, `CanVerticallyScroll`, `IsScrollInertiaEnabled`, `ScrollStartDistance` (default 8); private consts `InertialScrollSpeedEnd = 5`, `InertialResistance = ScrollGestureRecognizer.InertialResistance` (0.15), `MaxFlingSpeed = 6000`, `JitterPx = 4`, `MinFollow = 0.4`, `MaxCoast = 6 s`; `internal Point Damp(Point raw)`, `internal static double CoastShare(double t)`, `internal static Vector ClampSpeed(Vector v)`.
- `FlingTracker`: `const double WindowMs = 100`, `Reset(ulong ts, Point p)`, `Add(ulong ts, Point p)`, `Vector Velocity()`.
**Behaviour & rules:**
1. `Decide`: if |dx| < |dy|·1.2 → None; open row → Close when dx ≥ 60 else None (an open row can never start); closed: canStart and dx ≥ StartThreshold(rowWidth) → Start; canOpen and dx ≤ −120 → Open; else None.
2. SwipeRow listens to PointerPressed/Moved/Released with Tunnel|Bubble and handledEventsToo (the row content is a Button), de-duplicating the same args object; PointerCaptureLost cancels. `ClipToBounds = true`. `CanStart` = SwipeEnabled && StartCommand.CanExecute(null); `CanOpen` = SwipeEnabled && Actions != null && OpenWidth > 0.
3. Press: finish any slide in flight (`FinishMotion`), cancel the previous drag; ignore if swipe disabled or nothing possible; remember pointer, origin and `_from` (−OpenWidth when open else 0). The press is NOT handled (taps reach the button).
4. Move: until swiping, require |dx| ≥ 14 and |dx| ≥ |dy|·1.2; then set `:swiping`, add the pointer to the static `Claimed` set and `Capture` it (cancels the button click). Offset = clamp(_from + dx, left, right) with right = 0 if the row started open, else row width if CanStart else 0; left = −(OpenWidth + 24) if CanOpen else min(_from, 0). Handled.
5. Release while swiping: decide with `Decide(dx, 0, _from < 0, CanStart, CanOpen, Bounds.Width)` (only sideways travel counts once sliding). Open → IsOpen=true; Close → IsOpen=false; Start → IsOpen=false, slide to `Bounds.Width` over 160 ms, then execute `StartCommand` and snap home without animation; None → spring back to home (−OpenWidth if open else 0) over 180 ms. `LastAction` records the decision.
6. `Place(x)`: Offset and the row's TranslateTransform.X = x; `PART_Start` visible only when x > 5 mm·7.4 = 37 px (shown, never faded); `:armed` when x ≥ StartThreshold(width); tray opacity = `ActionsOpacity(x)` = 0 until the row travelled 37 px left, then linear to 1 at 120 px; `:revealed` when > 0.
7. Slides are stepped with `TopLevel.RequestAnimationFrame` (ease-out cubic `1 − (1−t)^3`, by wall clock), one slide at a time (a newer slide, a jump or a press retires the older one's frames and completion); backstop `DispatcherTimer.RunOnce(FinishMotion, ms + 120)`; no top level or ms ≤ 0 → land at once and run the completion. Changing `IsOpen` or `OpenWidth` re-settles (animated) unless dragging.
8. Recognizer press (touch/pen only): end previous gesture, track pointer, new gesture id, start point = damped = position in the target's own coordinate space (`Target as Visual`), reset FlingTracker.
9. Recognizer move: point = `Damp(position)` where follow = clamp(|delta|/4, 0.4, 1). Not yet scrolling: do nothing while `SwipeRow.IsClaimed(pointer)`; start scrolling when movement on an enabled axis exceeds `ScrollStartDistance` (absorb the start distance from the tracked point) and capture the pointer. While scrolling: delta = tracked − point, zeroing the non-scrollable axis; feed the velocity tracker; sum deltas and apply once per rendered frame (`RequestAnimationFrame`, immediately when no top level) by raising `ScrollGestureEventArgs(gestureId, delta)`; handled.
10. Release while scrolling: flush; v0 = `ClampSpeed(Velocity())` (cap 6000 px/s, direction kept), zero non-scrollable axis; no coast when v0 = 0, timestamps missing, > 200 ms since the last move, inertia disabled or no top level → end gesture. Coast: each frame raise a delta of `v0 · CoastSeconds · (CoastShare(t) − previous share)` with `CoastSeconds = −1/ln R` and `CoastShare(t) = 1 − R^t`; stop when the event is not handled, `ShouldEndScrollGesture`, > 6 s, or speed `v0·R^t` < 5 px/s on both axes; a new touch (new gesture id) stops it. `EndGesture` raises `ScrollGestureEndedEventArgs`. Capture lost → end.
11. `FlingTracker.Velocity`: keeps samples within the last 100 ms (at least 2); 2 samples → (p0 − p1)/span; else least-squares slope of x(t), y(t) negated (content direction); degenerate → two-point fallback.
**Configuration:** none
**Acceptance criteria:**
- A right drag past half the row (≥ 180 px) runs `StartCommand` once after the finishing slide; a shorter one springs back and runs nothing.
- A left drag of ≥ 120 px opens the tray; an open row dragged right ≥ 60 px closes and never starts.
- A diagonal/vertical drag scrolls the page and leaves rows alone; once a row is sliding the page does not scroll and a drifting finger still starts.
- A tap still selects the row; the tray stays invisible until the row has moved > 37 px left (pressed 0.8-opacity row never shows it).
- Fling speed follows a steady drag, a single stray sample does not define it, speed capped at 6000; the coast covers the same distance regardless of frame timing; jitter < 4 px is damped but a real drag is followed 1:1.
**Tests:** `SwipeRowTests` (12 cases incl. `A_right_swipe_starts_only_past_half_the_row`, `Putting_an_open_row_back_can_never_start_a_cure`, `Touching_a_row_while_it_springs_back_puts_it_home`, `Once_a_row_slides_the_page_does_not_scroll_and_a_drifting_finger_still_starts`), `TouchScrollTests` (6 cases), `DialogBlurTests.The_action_tray_stays_hidden_until_the_row_has_really_moved`.

**Files to create:**
- `Navigation/Route.cs` — `public enum Route`, `public static class RouteExtensions`
- `Navigation/INavigationService.cs` — `public interface INavigationService`
- `Navigation/NavigationService.cs` — `public sealed class NavigationService : INavigationService`
**Public contract:**
- `enum Route { Boot, Wake, Setup, Home, CureProcess, CureHistory, Alerts, Settings, Network, DevMenu, DevLedCalibration, DevHdt, Restart }` (13 values, this order).

### UI-11 — Boot page (logo → real hardware self-test → Setup / Home)
**Summary**
