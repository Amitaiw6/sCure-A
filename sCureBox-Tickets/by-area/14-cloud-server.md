## sCure Cloud portal — overview

The sCure Cloud portal is a **Google Apps Script web app** (V8 runtime) whose only storage is **one Google Sheet** ("sCure Cloud data") plus **one Drive folder** ("sCure DVT files") and the Apps Script **CacheService / PropertiesService**. Source folder: `cloud/google/` (portal build `0.9.146`). It replaced the Fly.io portal `cloud/portal.py` (deleted 2026-10); `Page.html` is now hand-edited, not generated.

**Files**

| File | Role | In git |
|---|---|---|
| `Code.gs` | the whole server: `doGet`, `doPost`, every `portal*` function the page calls, storage, auth, DVT queue | yes |
| `Page.html` | the single-page UI (CSS + markup + script in one file); first `<script>` is a `fetch` shim onto `google.script.run` | yes |
| `ErrorRegistry.gs` | `var ERROR_REGISTRY = {version, codes:{"<code>":{t,v?}}}` generated by `build_errors.py` | yes |
| `Secrets.gs` | `var SECRETS = {password, machineKeys, dvtKey, netbirdToken, netbirdPeers}` generated by `build_secrets.py` | **no** (`.gitignore` line 39) |
| `appsscript.json` | manifest: scopes, web-app access | yes |
| `.clasp.json` / `.claspignore` | clasp project binding / push allow-list | yes |
| `build_errors.py`, `build_secrets.py` | generators | yes |
| `test_*.cjs`, `test_page.py` | Node (vm fakes / puppeteer-core) and Python (playwright) tests | yes |
| `*.png` | screenshots (`live-simulation.png`, `run-window.png`, `simulation-howto.png`) | yes |

**Data flow**

```
CureBox firmware (PLAT-10 CloudSyncAgent) ──POST /exec {machineKey, snapshot | kind:report | kind:delete_reports}──▶ doPost
                                         ◀── {ok, acceptsReports, commands:[{id,type,payload}]} ──────────────────────
DVT tool (DVT/web/dvt-tool.html)  ──POST /exec {machineKey:<DVT key>, kind:"dvt_run"|"dvt_file"|"dvt_catalog"|...}──▶ doPost
DVT runner on a CureBox (DVT/runner/dvt-runner.cjs) ──POST /exec {DVT key, kind:"dvt_runner_hello"|"dvt_next"|"dvt_events"|"dvt_update"}─▶ doPost
                                                     ── firmware RemoteConfirm (DVT-05) gates every start AT the machine
Browser ──GET /exec──▶ doGet ──▶ Page.html ──google.script.run.portal*(token,…)──▶ Code.gs ──▶ Sheet / Drive / Cache
Browser ──GET /exec?report=…&m=…&t=… | ?dvtfile=…&t=… | ?code=…&state=… (Google OAuth return)──▶ doGet
Code.gs ──UrlFetchApp──▶ api.netbird.io (read-only peers) ; oauth2.googleapis.com/token (sign-in)
```

Machine commands are **data-only by design** (`upsert_program`, `delete_program`, `send_print`, `delete_print`); no command actuates hardware. DVT tests can be *requested* from the site but only start after someone presses Start on the CureBox screen (runner → firmware RemoteConfirm, DVT-05).

**Views of the page** (built by the other two ticket ranges; server functions they call are in CLOUD-04): top navigation `Overview`, `Machine`, `DVT`, `Race`, `Compare`, `Errors` (`data-view` = `overview|machines|dvt|race|compare|errors`) plus the header's People screen and dialogs (program editor, Send Simulated Print, DVT guide / simulation). Shell, Overview, Machines, Race, Compare, phone layout = CLOUD-20..39; Errors, DVT, Programs + editor, People, Simulation, other dialogs = CLOUD-40..59.

**Ticket list (server and platform):** CLOUD-01 project/manifest/deploy/build handshake · CLOUD-02 configuration and secrets · CLOUD-03 Sheets storage and migrations · CLOUD-04 routing and the page↔server call map · CLOUD-05 machine sync endpoint · CLOUD-06 alert log · CLOUD-07 error registry generator · CLOUD-08 cure reports · CLOUD-09 sessions, password sign-in, role gate · CLOUD-10 Google sign-in · CLOUD-11 people list and audit · CLOUD-12 machines API and data-only commands · CLOUD-13 NetBird status · CLOUD-14 DVT tool ingest · CLOUD-15 DVT read API · CLOUD-16 DVT units registry and race · CLOUD-17 DVT runner protocol · CLOUD-18 DVT site actions and change notification · CLOUD-19 test harness.

Cross-cutting server rules (every ticket):
1. All times stored as **unix seconds** (`now_() = Date.now()/1000`, fractional) unless stated (`audit.unix` and `users.lastLogin/added` are floored).
2. Every write path takes `LockService.getScriptLock().waitLock(20000)` and releases it in `finally`.
3. Endpoints never answer HTTP error codes (Apps Script cannot): failures are `{ok:false, message}` with HTTP 200. Page functions return `null` for "not signed in".
4. Long text (JSON, HTML) is split into `CELL_MAX = 45000`-character chunks over consecutive cells and joined back on read; on rewrite, a shorter value pads the row with `''` up to the sheet's last column so old chunks are cleared.
5. Never store a machine key (`delete d.machineKey` before storing). Never copy secrets into source; see CLOUD-02.

### CLOUD-01 — Apps Script project, manifest, clasp deploy and the build-reload handshake
**Project / folder:** cloud/google/appsscript.json, .clasp.json, .claspignore, Code.gs (`PORTAL_BUILD`, `setup`), Page.html (`PORTAL_BUILD`)
**Goal:** Create the Apps Script project that hosts the portal as a public web app executing as the deployer, define the push allow-list and the deploy procedure, and give open browser tabs a way to learn that a newer build was deployed.
**Depends on:** none
**Files to create:**
- `appsscript.json` — manifest.
- `.clasp.json` — `{scriptId: <the project id>, rootDir: "", scriptExtensions: [".js",".gs"], htmlExtensions: [".html"], jsonExtensions: [".json"], filePushOrder: [], skipSubdirectories: false}` (script id is the project's own; do not copy).
- `.claspignore` — ignore everything (`**/**`) then re-include `!Code.gs`, `!Secrets.gs`, `!Page.html`, `!appsscript.json`, `!ErrorRegistry.gs`.
- `Code.gs` — `var PORTAL_BUILD = '0.9.146'`; `function setup()` (run once from the editor: `book_()`, logs the sheet URL and the configured machine names).
- `Page.html` — `const PORTAL_BUILD = '0.9.146'` (must equal Code.gs).
**Public contract:**
- Manifest: `timeZone: "Asia/Jerusalem"`, `runtimeVersion: "V8"`, `exceptionLogging: "STACKDRIVER"`, `dependencies: {}`, `oauthScopes: [spreadsheets, script.scriptapp, drive, script.external_request]` (full URLs `https://www.googleapis.com/auth/...`), `webapp: {executeAs: "USER_DEPLOYING", access: "ANYONE_ANONYMOUS"}`.
- `portalDvt(...)` returns `build: PORTAL_BUILD` (CLOUD-15); the page shows a "Reload" banner (`location.reload()`) when `DVT.build && DVT.build !== PORTAL_BUILD`.
**Behaviour & rules:**
1. Anonymous access is required: the CureBox and the DVT tool/runner post without a Google login; the browser authenticates through the portal's own session (CLOUD-09/10).
2. `executeAs USER_DEPLOYING`: every Sheet/Drive/UrlFetch runs as the owner account.
3. Deploy procedure (from the SKILL file `.claude/skills/scure-cloud-ux/SKILL.md` and the `build_errors.py` docstring): in `cloud/google`, `npx @google/clasp push -f` then `clasp deploy -i <fixed deployment id> -d "<what>"`. A push alone does not change the live site; only a deploy to the fixed deployment id (the URL the machines are configured with) does. OPEN QUESTION: the exact clasp version to use is not in code (operator notes mention a clasp 3 alpha because of the login file format).
4. Bump `PORTAL_BUILD` in **both** Code.gs and Page.html on every change; a mismatch means the tab predates a deploy.
5. Adding an OAuth scope makes the web app need re-authorization by the owner before machines can sync again (comment at Code.gs `ownerEmail_`); scopes must be changed deliberately. `userinfo.email` is intentionally not requested.
6. `.claspignore` means only the five listed files are ever pushed; tests, generators and screenshots stay local.
7. `Secrets.gs` is pushed (it is in the allow-list) but never committed (git-ignored).
**Look & layout:** n/a (the reload banner itself is a UI ticket, CLOUD-20..39 / CLOUD-40..59).
**Configuration:** script id in `.clasp.json`; deployment id kept by the operator, never in source.
**Acceptance criteria:**
- `clasp push` uploads exactly Code.gs, Secrets.gs, Page.html, appsscript.json, ErrorRegistry.gs.
- The deployed URL answers GET with the portal page titled "sCure Cloud" to an anonymous browser and accepts anonymous POSTs at `/exec`.
- With Code.gs PORTAL_BUILD ≠ Page.html PORTAL_BUILD, the DVT views show a Reload banner.
- `setup()` creates the data sheet on a fresh project and logs its URL.
**Tests:** none automated for deploy (label untested); `test_page.py` stubs `build: '0.9.102'` in `portalDvt`.
**Reference (source):** cloud/google/appsscript.json 1-17; .clasp.json; .claspignore; Code.gs 734, 1505-1510; Page.html 611, 1167-1169, 1459-1461; .claude/skills/scure-cloud-ux/SKILL.md 10; build_errors.py 1-9.

### CLOUD-02 — Configuration and secrets (script properties, Secrets.gs fallback, build_secrets.py)
**Project / folder:** cloud/google/Code.gs (`cfg_`, `googleCfg_`, `execUrl_`, `ownerEmail_`), build_secrets.py, Secrets.gs (generated)
**Goal:** One place that resolves every secret and setting: Apps Script script properties win, a generated `Secrets.gs` is the fallback, and nothing secret is ever in git.
**Depends on:** CLOUD-01
**Files to create:**
- `Code.gs` — `cfg_()` returns `{password, keys, dvtKey, netbirdToken, netbirdPeers}`.
- `build_secrets.py` — reads `cloud/portal_secrets.local.txt` (git-ignored) and writes `Secrets.gs`.
**Public contract:**
- Script properties read: `PORTAL_PASSWORD`, `MACHINE_KEYS` (JSON `{"<machine name>": "<key>"}`), `DVT_KEY`, `NETBIRD_TOKEN`, `NETBIRD_PEERS` (JSON `{"<machine>": "<peer name>"}`), `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, `OAUTH_REDIRECT_URL`, `OWNER_EMAIL`; written by the server: `SHEET_ID`, `DVT_FOLDER_ID`, `RACE`, `dvt_renames_<id>`.
- `Secrets.gs`: `var SECRETS = {"password", "machineKeys", "dvtKey", "netbirdToken", "netbirdPeers"}` (first line comment "Generated by build_secrets.py … DO NOT COMMIT (git-ignored)").
- Source file line formats parsed by `build_secrets.py` (regex): `portal password: <v>`, `machine key (<name>): <v>` (repeatable), `dvt key: <v>`, `netbird token: <v>`, `netbird peer (<name>): <v>` (repeatable).
**Behaviour & rules:**
1. `cfg_()`: each value = script property if set, else `SECRETS.<field>`, else `''` / `{}`. `MACHINE_KEYS` / `NETBIRD_PEERS` that fail `JSON.parse` silently keep the fallback. If `SECRETS` is undefined the fallback is `{password:'', machineKeys:{}}`.
2. A machine's portal **name comes from its key**: the key map is the only machine registry; a machine cannot register itself. Adding a machine = adding a key to `MACHINE_KEYS` (script property needs no redeploy).
3. `build_secrets.py`: no source file → exit with "set PORTAL_PASSWORD / MACHINE_KEYS / DVT_KEY as script properties instead". No `dvt key:` line → mint one with `secrets.token_urlsafe(24)`, append it to the source file and print that it must be pasted into the DVT tool's Cloud box. Prints counts only, never values.
4. `googleCfg_()` = `{id, secret}` only when both GOOGLE_* properties are set (they are never read from Secrets.gs), else `null`.
5. `execUrl_()` = `OAUTH_REDIRECT_URL` if set else `ScriptApp.getService().getUrl()` (`''` on error).
6. `ownerEmail_()` = `OWNER_EMAIL` lower-cased/trimmed; else `Session.getEffectiveUser().getEmail()` (in production this needs the `userinfo.email` scope the manifest does not request, so it yields `''`), errors → `''`.
7. Never write a secret value into tickets, logs, commits or Page.html.
**Look & layout:** n/a
**Configuration:** `cloud/portal_secrets.local.txt` (git-ignored, `.gitignore` 35-39), script properties as above.
**Acceptance criteria:**
- With `MACHINE_KEYS` set as a property, Secrets.gs machine keys are ignored; with invalid JSON in the property, Secrets.gs keys are used.
- Running `build_secrets.py` without a `dvt key:` line adds exactly one to the source file; a second run reuses it.
- `git check-ignore cloud/google/Secrets.gs` succeeds.
**Tests:** test_code.cjs sets `PORTAL_PASSWORD`, `MACHINE_KEYS`, `DVT_KEY`, `NETBIRD_*`, `GOOGLE_*`, `OWNER_EMAIL` through a fake PropertiesService. `build_secrets.py` has no test (untested).
**Reference (source):** Code.gs 24-33, 47-58, 1166-1182; build_secrets.py 1-43; .gitignore 35-39.

### CLOUD-03 — Google Sheets storage, schema and in-place migrations
**Project / folder:** cloud/google/Code.gs (`book_`, `sheet_`, chunk helpers, `now_`, `json_`)
**Goal:** Open (or create) the single data spreadsheet, guarantee every sheet with its header exists, migrate older sheets in place without moving data, and provide the "long value over several cells" convention.
**Depends on:** CLOUD-02
**Files to create:** `Code.gs` — `book_()`, `sheet_(ss, name, header)`, `now_()`, `json_(obj)`, `CELL_MAX`; constant `DVT_UNIT_COLS`.
**Public contract:** the 12 sheets and their exact headers listed in the overview; script property `SHEET_ID`.
**Behaviour & rules:**
1. `book_()`: `SpreadsheetApp.openById(SHEET_ID)`; on missing id or open failure create `SpreadsheetApp.create('sCure Cloud data')` and store its id in `SHEET_ID`. Then ensure all sheets (in order): machines, commands, reports, alerts, dvt_runs, dvt_files, dvt_catalog, dvt_requests, dvt_runners, dvt_units, users, audit. Called at the start of nearly every server function.
2. `sheet_()`: if absent, insert, write header in row 1, freeze row 1, and delete the default first sheet named `Sheet1` or `גיליון1` when more than one sheet exists. Existing sheets are left untouched (header not rewritten).
3. Migration A (0.9.95): if `dvt_runs` column K header is `values`, `insertColumnBefore(11)` and write `machine` in K1 — rows move with it, so old values stay readable; a second pass is a no-op.
4. Migration B (0.9.145): if `dvt_requests` N1 ≠ `act`, write `act` in N1 (appended, nothing moves).
5. Chunking (`CELL_MAX = 45000`, a cell holds 50,000): split text into consecutive cells starting at the sheet's "blob" column; read with `slice(k).join('')`; on rewrite pad to `max(lastColumn, needed)` with `''`. An empty value still writes one `''` chunk.
6. Rows are located by scanning (`getLastRow()-1` data rows), ids assigned as `max(id)+1` under the script lock; row deletes go highest row first.
7. `json_(obj)` = `ContentService.createTextOutput(JSON.stringify(obj)).setMimeType(JSON)`.
**Look & layout:** n/a
**Configuration:** `SHEET_ID` (automatic).
**Acceptance criteria:**
- On an empty project, the first call creates the book with the 12 sheets and no `Sheet1`.
- A 900-program snapshot (> 45,000 chars) round-trips; writing a short one afterwards reads back short (old chunks cleared).
- A pre-0.9.95 `dvt_runs` row keeps its `values` JSON and reads `machine: ''` after migration; header length becomes 12 and stays 12.
**Tests:** test_code.cjs ("default sheet removed", "a snapshot longer than one cell is split", "a dvt_runs sheet from before the CureBox column … migrated", big catalog ~90 KB round-trip).
**Reference (source):** Code.gs 9-19, 39, 60-108, 608; test_code.cjs 4-33, 81-85, 109-113, 494-506.

### CLOUD-04 — Request routing (doGet / doPost) and the page↔server call map
**Project / folder:** cloud/google/Code.gs (`doGet`, `doPost`), Page.html (first `<script>`: the Apps Script shim)
**Goal:** Route every incoming HTTP request and define the exact list of server functions the page calls, through a `window.fetch` shim that keeps the page's REST-style code while calling `google.script.run`.
**Depends on:** CLOUD-03, CLOUD-09
**Files to create:**
- `Code.gs` — `doGet(e)`, `doPost(e)`.
- `Page.html` — shim: `tok()` / `setTok()` (sessionStorage key `scure-cloud-token`, in-memory fallback), `call(fn, ...args)` → Promise over `google.script.run.withSuccessHandler(res).withFailureHandler(rej)[fn](...)`, `window.scureReportHref(m, runId, download)`, `window.scureDvtFileHref(fileUrl, id)`, `reply(status, obj)`, `window.fetch = async (path, opts)`.
**Public contract:**
- `doGet(e)` order: `?report` → `serveReport_` (CLOUD-08); `?dvtfile` → `serveDvtFile_` (CLOUD-15); `?state` with `?code` or `?error` → `googleCallback_` (CLOUD-10); else `HtmlService.createHtmlOutputFromFile('Page').setTitle('sCure Cloud').addMetaTag('viewport','width=device-width, initial-scale=1').setXFrameOptionsMode(ALLOWALL)` (embeddable in Google Sites).
- `doPost(e)`: `path = e.pathInfo` trimmed of `/`; only `''` or `api/agent/sync` accepted, else `{ok:false, message:'not found'}`. Body = `JSON.parse(e.postData.contents || '{}')`, parse error → `{ok:false, message:'bad json'}`. `key = d.machineKey || e.parameter.key || ''`. If `String(d.kind)` starts with `dvt` → DVT branch (CLOUD-14/17) authenticated by `cfg_().dvtKey` (`{ok:false, message:'bad DVT key'}`), kinds `dvt_run, dvt_file, dvt_delete_runs, dvt_machines, dvt_catalog, dvt_runner_hello, dvt_events, dvt_next, dvt_update`, other → `{ok:false, message:'unknown DVT kind: <kind>'}`. Else machine branch (CLOUD-05/08) authenticated by the key map → `{ok:false, message:'bad machine key'}`.
- Shim path → server function (token = `tok()`; `null` result → status 401; `{denied:true}` → 403; `ok:false` → 400 where shown):

| fetch path (body fields) | server function |
|---|---|
| `/login` (`password`) | `portalLogin(password)` → stores token, 401 `{message or 'Wrong password'}` |
| `/login/mode` | `portalLoginMode()` (failure → `{google:false}`) |
| `/login/google` | `portalLoginStart()` |
| `/login/poll` (`state`) | `portalLoginPoll(state)` → stores token on `ok` |
| `/logout` | `portalLogout(token)` then clears token |
| `/api/me` | `portalMe(token)` |
| `/api/users` / `/api/users/save` (`email, role, name`) / `/api/users/remove` (`email`) / `/api/audit` | `portalUsers(t)` / `portalUserSave(t,email,role,name)` / `portalUserRemove(t,email)` / `portalAudit(t, 100)` |
| `/api/machines` | `portalMachines(t)` |
| `/api/alerts?since=<n>` | `portalAlerts(t, since)` |
| `/api/dvt` | `portalDvt(t)` |
| `/api/dvt/wait?since=<v>&wait=<s>` | `portalDvtWait(t, since, wait)` |
| `/api/dvt/detail` | `portalDvtDetail(t)` |
| `/api/dvt/race` (`start?, units?`) | `portalRaceSet(t, body)` |
| `/api/dvt/files` (`ids`) | `portalDvtFiles(t, ids)` |
| `/api/dvt/unit` (`unit, fields`) | `portalDvtUnitSave(t, unit, fields)` |
| `/api/dvt/approve` (`unit, testId, runIds, who, approve`) | `portalDvtApprove(t, unit, testId, runIds, who, approve !== false)` |
| `/api/dvt/request` (`machine, unit, testIds`) | `portalDvtRequest(t, machine, unit, testIds)` |
| `/api/dvt/cancel` (`ids` or `id`, `force`) | `portalDvtCancel(t, ids||id, force === true)` |
| `/api/dvt/acted` (`id`) | `portalDvtActed(t, id)` |
| `/api/dvt/answer` (`id, value`) | `portalDvtAnswer(t, id, value ?? null)` |
| `/api/machines/<name>/commands` (`type, payload`) | `portalCommand(t, decodeURIComponent(name), body)` |
| anything else | 404 `{ok:false, message:'not found'}` |

- Links: report = `<reportUrl>?report=<runId>&m=<machine>&t=<token>[&dl=1]`; DVT file = `<fileUrl>?dvtfile=<Drive id>&t=<token>`; `'#'` when the URL is empty.
**Behaviour & rules:**
1. Apps Script refuses anonymous POSTs with a path after `/exec`, so machines post to `/exec` itself; `api/agent/sync` is accepted for compatibility.
2. Apps Script cannot read request headers, so the key travels in the body (`machineKey`); `?key=` query is an alternative.
3. The DVT key can only write DVT data; a machine key can only write its own machine's data.
4. Apps Script HtmlService cuts a line at `//` even inside a regex (`\/\/`); write `\/{2}` in Page.html (checked by test_errors_page.cjs).
5. `window.fetch` is replaced globally, so all page network goes through the shim; there are no other server calls.
**Look & layout:** n/a
**Configuration:** none
**Acceptance criteria:**
- POST with pathInfo `other` → `ok:false`; with a bad key → `{ok:false, message:'bad machine key'}`; a DVT kind with a machine key → `bad DVT key`.
- Every row of the table above maps to an existing server function with the given argument order.
- GET with no parameters returns the page; with `report`/`dvtfile`/OAuth parameters it is routed as listed.
**Tests:** test_code.cjs (`post()` helper over `doPost`, bad key / bad path); every browser test stubs `google.script.run` with the same function names (CLOUD-19); test_errors_page.cjs checks no `\//` in Page.html.
**Reference (source):** Code.gs 1-8, 146-202, 1137-1145; Page.html 1-118.

### CLOUD-05 — Machine sync endpoint: snapshot storage and command delivery/ack (contract with PLAT-10)
**Project / folder:** cloud/google/Code.gs (`doPost` machine branch, `machines_`, `writeMachine_`, `commands_`)
**Goal:** Accept the periodic snapshot each CureBox posts, store it as that machine's latest state, merge its alert log, and hand back the data-only commands queued for it, marking them delivered and acknowledged.
**Depends on:** CLOUD-03, CLOUD-04, CLOUD-06
**Files to create:** `Code.gs` — machine branch of `doPost`, `machines_(sh)`, `writeMachine_(sh, name, text)`, `commands_(sh)`; constants `ONLINE_SEC = 90`, `COMMAND_TYPES`.
**Public contract (wire, both directions):**
- Request (from PLAT-10 `CloudSyncAgent.Snapshot`, application/json): `machineKey` (string, also sent as header `X-Machine-Key` which is unreadable here), `name` (string, ignored by the server — the name comes from the key), `state` `{chamberTemp, doorClosed, isHeating, isCooling, uvOn, internetOk, counters}`, `programs` (user materials), `presets` (built-in catalog), `prints` (≤ 20 print logs), `cures` (≤ 10 runs, no telemetry), `alertLog` `[{code, message, raised, cleared}]`, `ackIds` `[command id]`. No `kind` (or a kind other than `report` / `delete_reports` / `dvt*`) means a snapshot.
- Reply: `{ok: true, acceptsReports: true, commands: [{id: number, type: string, payload: object}]}`; errors `{ok:false, message}`.
- Commands sheet row: `id | machine | type | payload (JSON text) | created | delivered | acked` (times unix s).
- Command types and payloads (written by `portalCommand`, CLOUD-12; applied by PLAT-10): `upsert_program` payload = full program object; `delete_program` `{id}`; `delete_print` `{id}` (firmware 1.0.147+); `send_print` `{printName, printerName, materialName, nfcTag?}` (machine also honours optional `duration` minutes, `steps`, `csvFile`).
**Behaviour & rules:**
1. Resolve the name: the entry of `cfg_().keys` whose value equals the key; none → `bad machine key`. `delete d.machineKey` (never stored).
2. Under the script lock: remove `alertLog` from the body and merge it (CLOUD-06); write `JSON.stringify(rest)` to the machine's row (`name, now_(), chunks…`), creating the row if new. `ackIds` and `name` stay inside the stored snapshot.
3. For each command of this machine with empty `acked`: if its id is in `ackIds` → set `acked = now`; else parse payload (bad JSON → `{}`), add to `commands`, set `delivered = now`. So an unacked command is re-delivered on every sync until acked.
4. `acceptsReports: true` tells PLAT-10 it may upload reports (CLOUD-08).
5. A machine is **online** when `now - lastSeen < 90` s (sync every 30 s by default on the old agent; PLAT-10 default interval 10 s).
6. Report upload / delete kinds do not update `lastSeen`.

### CLOUD-17 — DVT runner protocol: hello, long-poll for work, command channel, progress updates
**Project / folder:** cloud/google/Code.gs (`dvtRunnerHello_`, `dvtCloseOrphans_`, `dvtNext_`, `dvtNextFull_`, `dvtEvents_`, `dvtUpdate_`, `runners_`, `touchRunner_`, `dvtRequests_`, `writeRequest_`, `pruneRequests_`, `dvtReadiness_`, `dvtWatching_`)
**Goal:** Relay DVT test requests to the runner on each CureBox (`DVT/runner/dvt-runner.cjs`) cheaply and quickly, and record its progress, prompts, steps, results and live machine state — the portal only queues and relays; the machine's own interlocks and the at-machine Start confirmation stay in charge.
**Depends on:** CLOUD-04, CLOUD-14, CLOUD-18; DVT-05 (RemoteConfirm at the machine)
**Files to create:** `Code.gs` — functions above; constants `DVT_RUNNER_ONLINE_SEC = 60`, `DVT_HOLD_MAX_SEC = 20`, `DVT_WATCH_SEC = 45`, `DVT_READY_FRESH_SEC = 45`, `DVT_REQUESTS_KEEP = 300`, `DVT_ACTIVE = ['queued','running','waiting','cancel_requested']`, `DVT_FINAL = ['done','failed','cancelled','blocked']`.
**Public contract (POST /exec with the DVT key):**
- `{kind:'dvt_runner_hello', machine, version?, unit?, catalog?:[…]}` → `{ok:true, closed:n}` / `the runner needs its CureBox name`. Upserts `dvt_runners` row (`machine, lastSeen, version, unit, catalog JSON (E..)`). (The runner also posts `dvt_catalog`, CLOUD-14.)
- `{kind:'dvt_next', machine, wait?: s, readiness?: object, live?: object}` → `{ok:true, request: null | {id, unit, testId}, watch: bool}`.
- `{kind:'dvt_events', machine, since?, wait?}` → `{ok:true, ver}` (command counter for that CureBox).
- `{kind:'dvt_update', id, machine?, status?, line?, prompt?, act?, runIds?, verdict?, live?}` → `{ok:true, cancel: bool, acted?: true, hasAnswer?: true, answer?}` / `no such request` / `that request belongs to another CureBox`.
- Sheet `dvt_requests` row: `id, machine, unit, testId, status, requested, started, finished, line, prompt JSON, answer JSON {v}, runIds JSON, verdict, act JSON`.
- Cache keys: `dvt_seen_<m>` (300 s), `dvt_ready_<m>` `{at, tests}` and `dvt_readysig_<m>` (300 s), `dvt_live_<m>` `{…live, at}` (300 s), `dvt_full_<m>` (6 h), `dvt_q_<m>` `'0'|'1'` (6 h), `dvt_cmd_<m>` counter, `dvt_watch`.
**Behaviour & rules:**
1. Hello is sent only between requests, so any of its machine's requests in `running`/`waiting`/`cancel_requested` were cut off by a restart: close them (`cancel_requested` → `cancelled`, line `cancelled - the runner restarted before it could stop the test`; others → `failed`, line `interrupted - the machine or its app restarted during the test; run it again`; prompt/answer cleared, finished = now), then prune. Queued stays queued.
2. `dvt_next`: store readiness (and bump the page version only when its JSON changed) and live state; loop: stamp `dvt_seen_<m>`; unless the cache says "nothing queued" (`dvt_q_<m> === '0'`) and the last full look is < 60 s old, do a full look under the lock (touch runner row, oldest queued request by id → status `running`, `started = now`, line `started on the CureBox`); answer as soon as a request is found; otherwise sleep 250 ms until `min(max(wait,0), 20)` s elapse, then `{request:null}`. `watch` = someone read the DVT tab within 45 s.
3. `dvt_events`: hold up to 20 s until `dvt_cmd_<m>` differs from `since`; return the current value.
4. `dvt_update`: under the lock; touch runner, stamp seen, cache live. `forced` = row already `cancelled` (force-stopped from the site); `cancel = cancel_requested || forced`. Unless forced: copy `line`, `prompt`, `act` when present in the body. If the stored `act.pressed` was set by the site → reply `acted:true` once and mark `act.acked`. `runIds` (strings) and `verdict` copied when given. A stored answer is handed over once (`hasAnswer`, `answer = answer.v`) and cleared together with the prompt. Status: forced → prompt/act cleared, status kept; final status → set, `finished = now`, prompt/act cleared, then prune; `running`/`waiting` → set only when no cancel is pending.
5. Pruning keeps the newest 300 final requests; active ones are never pruned.
6. Safety: no portal path starts hardware; the runner must obtain Start at the machine (DVT-05) before running, and runs through the machine's own API.
7. OPEN QUESTION: `dvt_update` without `machine` is accepted for any request id; the runner's `machine` is self-declared under the shared DVT key.
**Look & layout:** n/a
**Configuration:** `DVT_KEY`.
**Acceptance criteria:**
- With nothing queued, consecutive `dvt_next` polls within 60 s read no sheet; a request queued meanwhile is returned by the very next poll.
- A held `dvt_next` (wait 1 s) answers empty after its hold, and returns a request queued during the hold long before it ends; `wait: 999` is capped at 20 s.
- `dvt_events` wakes on a cancel/answer/request for its own CureBox only.
- A cancel while running is reported as `cancel:true` and a later `status:'running'` does not overwrite `cancel_requested`.
- `blocked` is final: leaves the active list and is stamped finished.
- Hello closes orphaned running requests and keeps queued ones.
**Tests:** test_code.cjs 275-444, 554-589.
**Reference (source):** Code.gs 724-963; DVT/runner/dvt-runner.cjs 127-166, 449-450 (client).

### CLOUD-18 — DVT actions from the site and change notification (request, cancel, answer, acted, approve, long poll)
**Project / folder:** cloud/google/Code.gs (`portalDvtRequest`, `dvtOpenOthers_`, `portalDvtCancel`, `portalDvtActed`, `portalDvtAnswer`, `portalDvtApprove`, `portalDvtWait`, `waitFor_`, `bumpVer_`, `bumpCmd_`, `bump_`)
**Goal:** Let service users queue DVT tests on a CureBox, stop them, answer the runner's questions and confirm manual steps; let admins approve hand-made electrical-safety tests; and push "something changed" to open DVT tabs and runners within a second through version counters and long polls.
**Depends on:** CLOUD-09, CLOUD-14, CLOUD-17
**Files to create:** `Code.gs` — functions above.
**Public contract:**
- `portalDvtRequest(t, machine, unit, testIds)` → `{ok:true, queued, skipped}` / `choose a CureBox, a unit and at least one test` / `<machine> is unit <unit> - the request was for <unit>. Reload the page.` / `<ids> runs last - <n> other test(s) on <unit> have no result yet`.
- `portalDvtCancel(t, id | [ids], force)` → `{ok:true, stopped}` / `that request is not active` / `none of those requests is active`.
- `portalDvtActed(t, id)` → `{ok:true}` / `that request is not waiting for you to do anything` / `that step is watched by the machine itself - nothing to press`.
- `portalDvtAnswer(t, id, value)` → `{ok:true}` / `that request is not waiting for an answer`. Value: `true` Done/Yes, `false` No, `null` Skip, or the typed value.
- `portalDvtApprove(t, unit, testId, runIds, who, approve)` → `{ok:true, approved}` | `{ok:true, deleted}` | messages `only the hand-made electrical safety tests are approved from the site`, `no runs to approve`, `run <id> does not belong to <testId> on <unit>`, `write who approves`.
- `portalDvtWait(t, since, waitSec)` → `null` or `{ver}` (string); cache `dvt_ver` counter.
**Behaviour & rules:**
1. Request: service role; once the CureBox's runner announced its unit, a request for another unit is refused (stale tab). A test with `afterAll` in the catalog is refused while any other test owed on that unit (`t.units` contains unit; owed run keys `t.runs` or `['|1']`) lacks a `PASS|FAIL|BLOCKED|WAIVED` run with runId `<tid>|<unit>|<key>`. Tests already active for that machine+unit are skipped (and duplicates in one call). New rows: `[id++, machine, unit, tid, 'queued', now, '', '', 'waiting for the CureBox to pick it up', '', '', '[]', '']`; then `dvt_q_<m> = '1'` and `bumpCmd_(machine)`.
2. Cancel (service): queued → `cancelled` (`cancelled from the site before it started`); running + `force` → `cancelled`, prompt/act/answer cleared (`stopped from the site (forced)`); running without force → `cancel_requested` (`stopping - the CureBox turns everything off`). `bumpCmd_` for each affected machine.
3. Acted (service): refuse when no `act` or `act.ack === false`; set `act.pressed = act.acked = true`; `bumpCmd_`.
4. Answer (service): requires an open prompt; store `{v}`; line `answered from the site - the CureBox continues`; `bumpCmd_`.
5. Approve (admin): only catalog group `ELE`; every runId must start `<testId>|<unit>|`. Approve writes one `PASS` row per run not already PASS (`operator` = Google name `<email>` or email; with the shared password the typed `who`, ≤ 60 chars), `note = 'Approved on the site by <name>'`, `startedAt` = ISO now, `machine ''`. Withdraw deletes only rows whose note starts `Approved on the site`.
6. Change notification: `bumpVer_()` increments `dvt_ver` (6 h TTL) on every request write, DVT ingest, unit/race change and readiness change; `bumpCmd_(m)` increments `dvt_cmd_<m>` and `dvt_ver`. `portalDvtWait` stamps `dvt_watch` and holds up to `min(waitSec, 20)` s (page asks 15) until `dvt_ver` ≠ `since`; `waitFor_` polls every 250 ms.
7. Page cadence (for reference, implemented in UI tickets): long poll `/api/dvt/wait?since=…&wait=15` while the DVT view is open; on change reload `portalDvt`; retry after 3 s on failure; safety-net refresh 8 s on DVT, 10 s elsewhere.
8. Safety: requesting never actuates; the CureBox asks for Start at the machine (DVT-05).
**Look & layout:** n/a (DVT view: CLOUD-40..59)
**Configuration:** none
**Acceptance criteria:**
- Requesting the same test twice while queued queues it once (`skipped:1`).
- A request for `UUT-02` on a runner that said `UUT-01` is refused.
- An `afterAll` test is refused while another test on the unit has no result.
- A force-stop closes the row at once and the runner's next update returns `cancel:true` without reviving it.
- A viewer's call to any of these returns `denied:true`; approve by a service user is denied.
- `portalDvtWait` returns as soon as any of the listed changes happens.
